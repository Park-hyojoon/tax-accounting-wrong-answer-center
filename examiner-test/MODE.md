# 출제위원 테스트를 명시적으로 요청한 경우만 읽기

일반 등록·수정·태그 분류·오답 관리에는 이 문서, analysis.js, private/ 원문을 읽지 않는다.

## 좁은 진입점

1. 요청이 출제위원 테스트/출제위원 모드인지 확인한다.
2. examiner-test/README.md와 사용자가 화면에서 만든 출제 요청만 읽는다.
3. analysis.js는 최초 분석 때 만든 요약이다. 원문을 매번 다시 읽지 않는다. private/theory-index.json은 근거가 불충분한 해당 문항을 감사해야 할 때만 읽는다.
4. 5~8개 이론 4지선다만 생성하고, 한 묶음은 8개를 넘기지 않는다. 새 문제는 전용 JSON 가져오기를 사용한다. 기존 data/*.js, META, 원장에 넣지 않는다.
5. 기출 빈도와 시험범위를 별개로 본다. 후보 목록 밖 개념도 금지된 것은 아니지만, 먼저 공식 교재·기준·법령의 범위 근거를 확인한 뒤 개념 목록 확장을 제안한다.
6. 123~127회 이론 75문항 표본으로 실무 포함 전체 빈도·최근 수년 장기 미출제·출제 확률·사용자 교재 중요도를 단정하지 않는다. 관찰되지 않은 개념은 미관찰 후보로 표시한다.
7. 숫자만 교체하지 말고 원칙의 적용 방향, 개념 결합, 예외의 경계를 바꾼다. 계산 부담을 올려 난이도를 꾸미지 않는다.
8. 단일정답·선택지별 반증·자연스러운 문장·근거·범위를 검토한다. AI의 검토를 인간 검토나 실제 시험 적합성 인증으로 표현하지 않는다.
9. 법령 문제는 현행 시행일을 확인한다. 모순이나 근거 부족이 있으면 해당 문항은 출제 보류한다.
10. 문제 바로 아래에서 채점하고 접힌 정답을 확인한다. 자료표는 table 구조로 유지한다. 제목과 풀이 전 화면에서 정답이나 결정적인 함정을 누설하지 않는다.

## 이번 시범의 경계

- 시범 6개는 이 대화의 AI가 출제한 정적 검토본이다. 스타일 조합 버튼은 시범본 선택이며 실시간 AI 생성이 아니다.
- API 키·서버·외부 모델 호출·빌드 도구·UI 라이브러리를 추가하지 않았다.
- 사용자 승인 후 가져온 묶음은 시험 정답 인증이 아니라 이 실험에서 사용하겠다는 승인이다.
- 테스트의 기록은 별도 브라우저 저장 및 명시적 백업/복원만 한다. 기존 동기화에는 포함하지 않는다.
- Anki/FSRS 간격 반복은 이번 범위가 아니다.
